# w24 allocation, memory and CPU reduction

The updated **throughput scaling is unconfirmed**: all twelve paired
populations on i270/r7900x fail unchanged shared-host resource gates.
The following standalone allocation, RSS and hardware-counter measurements
are diagnostic evidence of reduced memory and CPU work. They are not
confidence intervals for inference latency. No experimental arithmetic or
tiling feature was promoted.

The implementation removes serial row scheduling vectors, uses fixed graph
metadata and stack concatenation references, retains last-use activation
storage in each inference context, removes full depthwise padding and the
non-overlapping transpose padding copy, and shares immutable packed weights
between active std instances. Ordered arithmetic is preserved.

## Memory and allocation results

All rows below are matched standalone probes on one i270 performance core.
GNU time measures process maximum RSS across construction plus 101 calls;
these are not steady-state live-heap measurements.

| Deployment | Baseline calls/image | Candidate calls/image | Baseline peak RSS, KiB | Candidate peak RSS, KiB |
|---|---:|---:|---:|---:|
| std, runtime SIMD | 190.78 | 1 | 90732 | 15304 |
| alloc-only, generic scalar | 321 | 16 | 14684 | 13816 |

The std differential is 19,078 versus 100 calls over 100 extra images. Its
remaining allocation is the caller-owned map. Eight std workers measure
325 calls over 320 additional images: 320 maps, one shared-pool miss and four
infrastructure calls. The measured average is 1.015625 calls/image; this is
not a zero-miss guarantee under arbitrary concurrency.

Alloc-only's 1,600 calls over 100 extra images comprise 1,300 activation
allocations, 200 dense packing-scratch allocations and 100 output maps.
Without std there is no shared NN pool or TLS packing cache. The private
workspace retains at most 2 MiB of idle activation capacity, evicting large
spares to keep peak RSS below the old runtime. It deliberately trades some
reuse for lower retained memory. The early unrestricted-cache pilot instead
increased alloc-only RSS; that pilot and the 4 MiB pilots are preserved.

### Which pattern needs which treatment

| Pattern | Implemented treatment | Why a general pool is insufficient |
|---|---|---|
| 129 serial dense row-schedule vectors/image | Borrow output row slices directly; one packing scratch loan spans the convolution | Metadata disappears rather than needing recycling |
| Graph values/use counts and concat references | Fixed graph arrays and stack references | Known graph size requires no recurring allocator work |
| Input, pointwise/depthwise, concat, clone and mean storage | Inference-owned best-fit activation workspace; recycle only after last use | Predictable liveness avoids cross-worker competition for these buffers |
| Full padded depthwise inputs and 2x2 transpose padding | Direct source reads, explicit zero border arithmetic | Removes copying as well as allocator churn |
| Shared CNN tensor outputs and variable-shape paths | Keep the existing bounded process-wide pool and its accounting/limits | Useful fallback where the shared kernels own output allocation |
| Fresh zeroed blocked tensors | bytemuck 1.25.2 try_zeroed_vec with existing allocation-error mapping | Makes allocation fallible through alloc_zeroed; does not itself reduce allocation count |
| Returned saliency map | One owned Vec under the existing API | Caller-buffer output would require a separately approved API change |

Each active model has separate execution buffers. std instances share an
Arc of immutable packed kernels per lane layout through weak cache entries;
dropping the final instance releases those weights. This avoids a permanent
strong model cache. Retained workspace buffers remain charged as live NN
memory; general pool limit/release semantics are unchanged.

|---|---:|---:|---:|---:|
| Serial driver, 1001 calls | 29.4% | 16.4% | 20.8% | 24.6% |

Eight-worker process peak RSS is 279,840 versus 153,240 KiB; minor page faults
are 1,298,140 versus 68,659 and system CPU time 2.14 versus 0.10 seconds.
One-worker driver RSS is 174,292 versus 119,480 KiB. These driver RSS values
include the identical serial oracle startup plus the 32-image fixture; that
startup creates an RSS floor even though its unused pool is released before
workers exist. Use the standalone table for single-model deployment memory.

Lower fault/copy/allocation work and fewer memory-bound slots support the
buffer-reuse approach. The larger core-bound fraction describes the remaining
work; these counters do not establish a DRAM-bandwidth ceiling or a reduction
in hardware memory latency itself. Pure scalar fused arithmetic dominates the
alloc-only CPU totals, so its instruction reduction is much smaller.

### Intermediate regression corrected

Removing padding initially left a border closure outlined outside its SIMD
feature context. `sudo perf record` attributed 17.48% of userspace cycle
samples to a vector FMA bridge and 10.81% to the outlined border closure.
That version used 24,245,772,998 cycles for 1001 calls, more than the baseline.
The forced-inline private border helper in 84d927d5 preserves target features
and brings the matching probe to 16,884,021,647 cycles. The rejected binary,
traces, failed recording command and repaired recording are retained.

## Scaling confirmation limitation

The v2 worker fixture creates one frozen serial oracle, releases its unused
pool, then constructs both persistent worker groups. Workers pin to physical
CPUs and compare every assigned output bit against the oracle before timing.
Both arms handle the same 32 preprocessed inputs per callback. Their callbacks
are interleaved across five fresh processes and ten rounds per process.
The paired process RSS includes both groups and is not a deployment RSS result.

All four i270 populations and both complete four-width r7900x attempts are
invalid: twelve of twelve fail resource gates. Initial launch failures are
also retained. i270 observed foreign Codex/herdr activity and CPU-load gates;
the traced r7900x run observed foreign herdr, Claude and nomad activity.
No foreign process was stopped, resource gate changed, noisy round removed,
or incomplete population promoted. Accordingly no new scaling speedup is
claimed. The earlier valid single-arm v1 scaling figures remain historical.
The JSON retains descriptive means for audit, labeled invalid.

The Linux launcher uses bounded root system scopes, then the original user:
this host's user manager accepts AllowedCPUs without a delegated cpuset
controller, which did not enforce the requested boundary. The successful
launches prove the exact requested process set in zenbench. Admission still
fails on shared-host activity, independently of placement.

## Correctness and validation

Both sigmoid modes match the frozen runtime bit for bit on 32 distinct inputs
in pure std and pure alloc-only executables. Explicit AVX-512 also matches on
32 inputs per sigmoid mode. Existing independent operator, strided-input,
scalar/SIMD, poisoned-workspace and fused/unfused checks pass, including
required actual v4 execution. Bare-metal aarch64-unknown-none checks pass.
No public signatures or numerical expectations were relaxed.

The frozen 257-image / 992-source-size validation passes 1,984 candidate
comparisons against tract: zero salient-region edge movement, zero final-crop
edge movement, zero presence mismatches and zero violations of the approved
three-map-pixel budget. Maximum map absolute difference is 1.043081284e-5;
tract remains a numerical oracle, not a bitwise one. These inputs were not
used for fitting or model selection.

The NN changes pass every required CI platform at 677d69be, all 50 stored
decoder-reference cases (including tier/thread parity), independent operators,
and all 16 CLI roundtrips with actual checkpoints. Full encoder-reference
coverage was not rerun. The consumer's required CI status is recorded with
the review; API snapshots and all-feature Clippy also pass locally.

run-heavy peaks: 0.36 GiB for the final four-deployment memory study; 0.69 GiB
for the worker counter/geometry suite; 0.15 GiB for eight-worker heaptrack;
0.09 GiB for the r7900x AVX2 probe and 0.47 GiB for explicit AVX-512 build,
parity and profiling. These wrapper peaks include tooling; deployment RSS
comes from GNU time above.

Normal/build dependency count is now 16, adding bytemuck to the former 15.
The same 706,570-byte gzip model remains embedded; no weights were changed.
No release is requested. Raw artifacts and their verified independent mirror
are described in [the artifact pointer](w24_memory_cpu_2026-11-07.pointer.md).
